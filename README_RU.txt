ПОДГОТОВКА ДЛЯ GITHUB ACTIONS
==============================

Файлы:
- bot.py — один проход сканирования; подходит для запуска по расписанию, не бесконечный цикл.
- requirements.txt — зависимости.
- .github/workflows/scanner.yml — запускает сканер примерно каждые 5 минут и позволяет запустить вручную.

Настройка репозитория:
1. Создай репозиторий на GitHub. Для бесплатного использования стандартных runners без лимита минут он должен быть PUBLIC; тогда код будет виден всем. Если не хочешь делать код публичным, остановись и проверь квоту бесплатных минут для private-репозитория.
2. Загрузи bot.py, requirements.txt и папку .github/workflows/scanner.yml.
3. В репозитории открой Settings -> Secrets and variables -> Actions -> New repository secret.
4. Создай секрет TELEGRAM_BOT_TOKEN (значение — токен Telegram-бота).
5. Создай секрет TELEGRAM_CHAT_ID (значение — Chat ID).
6. Открой Actions и разреши workflows, если GitHub попросит.
7. Открой workflow "Fibonacci Telegram Scanner" и нажми Run workflow для первого теста.
8. Открой run и проверь логи. Успех обычно отображается зелёной галочкой.

ВАЖНЫЕ ОГРАНИЧЕНИЯ:
- GitHub Actions не держит процесс непрерывно. Он запускает отдельный скан примерно каждые 5 минут; расписание может задерживаться.
- Это НЕ гарантированный 24/7 сервис. Для M15-сигналов запуск каждые 5 минут может быть достаточным для проверки закрытых свечей, но уведомления не мгновенные.
- В публичном репозитории виден код, но GitHub Secrets не публикуются. Никогда не вставляй токен в код или обычные файлы.
- Включена запись bot_state.json в репозиторий для сохранения активных сетапов между запусками. Это может создавать коммиты при изменении состояния.
- Не создавай ордера автоматически. Проверяй сигналы на графике вручную.
- Стратегия экспериментальная, не обещает прибыль.
